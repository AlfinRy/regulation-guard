## Regulation Knowledge Base for RegulationGuard

## HIGH-Risk Patterns for ISO 27001 Compliance

**Undefined Security Standards**
- Encryption standards left to vendor discretion with no minimum specified.
- Security standards that "may change without notice" — changes to security
  configuration must be documented, approved, and communicated.
- No reference to recognized standards (AES-256, TLS 1.2+, etc.).

**No Mandatory Security Assessment**
- No requirement for periodic penetration testing.
- No vulnerability assessment schedule.
- Vendor can opt out of security testing "when management deems necessary."
- No right for the client to conduct or commission security audits of the vendor.

**No Security Incident Response**
- No documented incident response process required from vendor.
- No escalation path for security events.
- Vendor not required to participate in incident response exercises.

**Physical Security**
- No specification of physical security requirements for data centers.
- Data centers with no mention of access controls, CCTV, environmental controls.

**Change Management**
- System changes made without notification to client.
- No change approval process for production systems handling client data.
- Emergency changes with no retrospective review required.

**Access Control**
- Shared accounts or credentials for accessing client systems.
- No requirement for multi-factor authentication.
- No regular access review or deprovisioning process.

## Key ISO 27001:2022 Controls Relevant to Vendor Contracts

**A.5 — Organizational Controls**
- A.5.19: Information security in supplier relationships
  Policies and procedures for managing supplier relationships must exist
- A.5.20: Addressing information security within supplier agreements
  Contracts must include security requirements, incident notification obligations,
  audit rights, and data handling requirements
- A.5.21: Managing information security in the ICT supply chain
  Third-party risk must extend through the supply chain (subprocessors)
- A.5.22: Monitoring, review, and change management of supplier services
  Regular review of supplier security performance required

**A.8 — Technological Controls**
- A.8.5: Secure authentication — MFA required for privileged access
- A.8.7: Protection against malware
- A.8.8: Management of technical vulnerabilities — patch management required
- A.8.12: Data leakage prevention
- A.8.24: Use of cryptography — encryption policies must be documented
  and minimum standards specified; cannot be left to vendor discretion
- A.8.25 — A.8.29: Secure development lifecycle requirements

**A.12 — Cryptography (mapped from ISO 27001:2013, still applicable)**
- Encryption policies must be defined and documented
- Key management procedures required
- Minimum encryption standards must be contractually specified
- "Encryption at our discretion" clauses are non-compliant

**A.18 — Compliance / Security Assessment**
- Regular review of information security policies and technical compliance
- Periodic information security assessments required
- Penetration testing must be performed by qualified, independent parties
- Vulnerability assessments must be conducted at defined intervals
- Results must be documented and remediation tracked

## Security Assessment Requirements

### Mandatory Assessments

| Assessment Type | Minimum Frequency | Who Performs |
|---|---|---|
| Penetration testing | Annual | Qualified independent third party |
| Vulnerability assessment | Quarterly | Can be internal or external |
| ISMS internal audit | Annual | Internal auditor (independent of IT ops) |
| Supplier security review | Annual | Client risk team |

### Contractual Requirements for Vendors

Vendor contracts must:
1. Require the vendor to conduct annual penetration tests and share results with client
2. Allow the client to commission independent security assessments of the vendor
3. Require remediation of critical/high findings within 30 days
4. Prohibit the vendor from waiving or indefinitely deferring security assessments

**Non-compliant example:**
"PIHAK KEDUA tidak berkewajiban melakukan penetration testing atau vulnerability
assessment secara berkala, namun akan melakukan pengujian apabila dipandang perlu."
→ VIOLATION — Explicitly waiving periodic security assessment requirements
   conflicts with ISO 27001 A.18 and POJK 38/2019 IT Security Assessment annex.

### What "Industry Standard" Means

Clauses that reference "industry standard security" without specification are
insufficient. ISO 27001 requires explicit documentation of:
- Encryption algorithms and key lengths
- Authentication methods (and whether MFA is required)
- Logging and monitoring requirements
- Incident response procedures and timelines
